# Bot Decision Audit

Updated: 2026-09-15

이 문서는 `balance/bot-decision-v2`의 실제 의사결정 정책을 증강 단위로 점검한 기록이다.

## 공통적으로 상태 평가를 사용하는 영역

- 일반 말/결과/경로 선택: `legalMoveOptionsWithAugments`가 만든 모든 합법 이동 후보를 실행한 뒤 `outcomeScore`로 비교한다.
- AUG-015 재배치: 사용하지 않음과 가능한 그룹을 모두 비교한다.
- 일반 업기: 업기/따로 두기를 비교한다.
- AUG-043 독불장군: 일반 업기 후보와 아군 잡기 후보를 함께 비교한다.
- AUG-012 아깝다: `balance/bot-decision-v2`에서 도 유지와 재던지기 기대값을 비교한다.
- AUG-044 신의 손: `balance/bot-decision-v2`에서 도/개/걸/윷/모를 상태 평가 + 1-step 이동 탐색으로 비교한다.

## 특수 승리형에 이미 들어간 목표 점수

`src/lib/simulation/game.ts`의 기존 `playerPositionScore`는 다음 목표를 별도 평가한다.

- AUG-031 문워크: 대기 상태 복귀와 역방향 진행
- AUG-032 사방신: 네 갈림길 점유 수
- AUG-033 우주의 중심: 중앙 점유, 집결, 중앙 접근
- AUG-041 독주: 누적 바퀴 수와 대표 말 진행
- AUG-042 추노: 누적 상대 잡기 수

따라서 Sim-Runner의 일반 이동 정책은 실제 게임 봇보다 이 특수 목표들을 더 잘 반영한다.

## 전수 점검에서 확인된 고정 휴리스틱/미적용

### 획득 선택

- 자연 증강 선택은 3장 중 `rng.augment.pick`이다. 현재 판 상태와 증강 조합 가치를 평가하지 않는다.
- AUG-048/049는 규칙 자체가 무작위 Gold/Prism 획득이므로 무작위가 정상이다.

### AUG-011 반격의 서막 / AUG-039 양자택일

두 결과 중 `기본 이동 칸 + 추가 던지기 보너스`만으로 선택한다. 실제 다음 상태 후보를 비교하지 않는다.

### AUG-024 칸은 숫자에 불과하다 1

현재 정책은 가장 큰 4칸 이상 결과를 골라 거의 반반으로 나눈 뒤, 일반 이동보다 먼저 실행한다. 분할하지 않기와 모든 분할값을 상태 평가로 비교하지 않는다.

### AUG-028 내일의 나에게

사용 가능한 결과가 2개 이상이면 가장 작은 이동 결과를 무조건 저장한다. 저장하지 않기와 각 저장 후보의 미래 가치를 비교하지 않는다.

### AUG-026 보험 들었습니다

보호할 말은 setup에서 참조하는 대표 말을 피하는 휴리스틱을 우선한다. 가능한 말들을 상태 전이로 전부 비교하지 않는다.

### AUG-035 일타쌍피

추가 잡기 대상 중 말 수가 가장 많은 묶음을 선택한다. 상대의 특수 목표, 위치, 후속 상태 가치를 비교하지 않는다.

### AUG-038 대동단결

말판 위 그룹이 3개 이상이면 즉시 사용하고 가장 진행한 그룹을 기준점으로 삼는다. 사용하지 않기, 사용 시점, 모든 기준 그룹을 상태 평가로 비교하지 않는다.

### AUG-046 뽑기 기계

내 말은 덜 진행한 말, 상대는 더 진행한 말을 기준으로 고정 휴리스틱 비교 후 내 말은 29번, 상대 말은 1번을 희망 위치로 지정한다. 가능한 대상/위치/사용하지 않기를 전부 비교하지 않는다.

### AUG-056 웜홀

사용 가능하면 진행도가 가장 낮은 그룹을 우선 웜홀에 넣는다. 웜홀 사용 여부와 모든 그룹의 기대값을 비교하지 않는다.

### AUG-058 토끼와 거북이

획득 시 대기 중인 자신의 말 중 하나를 무작위로 선택해 완주 직전으로 보낸다. 어떤 말을 보낼지 상태/대표 말 관계를 평가하지 않는다.

### AUG-030 에이스 / AUG-041 독주 대표 말

공통 setup 시스템이 상태, 진행도 기반 휴리스틱으로 대표 말을 정한다. 실제 이후 게임 가치를 비교하는 탐색은 아니다.

### AUG-059 여백의 미 관련 잔존 코드

현재 카탈로그 설명은 완주에 따라 바깥 변이 줄어드는 규칙이다. 시뮬레이터에는 과거의 명시적 margin send/return API와 `maybeUseMarginExit` / `maybeReturnMargin` no-op이 함께 남아 있다. 현재 규칙 계약과 레거시 코드의 정합성을 별도 확인해야 한다.

## 자동 효과로서 별도 선택 AI가 필요 없는 영역

아래와 같은 증강은 플레이 중 별도 버튼 선택이 없거나 규칙상 무작위/자동이므로, 게임 엔진이 후보 상태에 효과를 반영하면 일반 이동 평가를 통해 간접적으로 고려된다.

- 이동량/던지기 변형 계열
- 잡기 면역/방어 계열
- 개판, 고정 던지기, 도 확률 제거
- 골목대장, 성역, 고가도로
- 청소부, 물귀신, 역병
- 중력 폭발, 폭탄, 대격변
- 메아리
- 산책로
- 강해져서 돌아오마
- 배반의 무작위 상대 이전 부분

## 현재 가장 큰 정책 불일치

1. 실제 게임 봇은 특수 승리 목표 점수가 부족하지만 Sim-Runner는 AUG-031/032/033/041/042를 별도 평가한다.
2. 실제 게임 봇은 G13/P11/P17 능동 행동 일부를 아예 사용하지 못한다.
3. Sim-Runner는 같은 기능이 있더라도 AUG-024/028/038/046/056 등에서 상태 평가 대신 고정 휴리스틱을 사용한다.
4. 두 구현의 증강 선택 정책도 각각 timeout/random 기반이라 실제 플레이어 수준의 조합 선택을 재현하지 않는다.

따라서 현재 `balance/bot-decision-v2`는 신의 손/도 리롤 개선 브랜치이지, 모든 선택형 증강의 범용 의사결정이 완료된 브랜치가 아니다.
